Sistema de Gestión para Distribuidora

En producción

Sistema que opera a diario las ventas, el inventario en tiempo real, los precios dinámicos, las cuentas de crédito y los reportes de caja de una distribuidora real en Antioquia que mueve 500–700 canastas diarias, con picos de 900.

  • Java 17
  • Spring Boot 3.2
  • PostgreSQL 15
  • JUnit 5
  • Mockito
  • Docker
  • Maven
Ver detalles técnicos

Problema Una distribuidora que mueve cientos de canastas al día gestionaba ventas, inventario, crédito y caja de forma manual: necesitaba precisión monetaria exacta y trazabilidad de cada movimiento.

Decisión técnica clave Usé BigDecimal en lugar de double para todos los cálculos de dinero y evitar errores de redondeo en precios y saldos, y modelé el dominio con DDD (value objects Dinero, Precio, Cantidad) para reflejar las reglas reales del negocio.

Destacado En producción operando 500–700 canastas diarias (picos de 900): inventario en tiempo real, precios dinámicos, cuentas de crédito y reportes de caja, con límite de intentos de login.

En números 173 pruebas (JUnit 5 + Mockito) · 37 endpoints en 11 controladores · value objects para el dinero.

Automatización de pedidos por WhatsApp con IA

Mayo 2025

Backend que interpreta mensajes de WhatsApp con GPT-4o, registra pedidos automáticamente y gestiona su ciclo de vida completo. Incluye panel admin con JWT, webhooks validados con HMAC-SHA256 y deploy en Railway.

  • Python 3.11
  • FastAPI
  • PostgreSQL
  • OpenAI GPT-4o
  • Meta Cloud API
  • Docker
  • Railway
Ver detalles técnicos

Problema Los negocios que reciben pedidos por WhatsApp los gestionan a mano: es lento, se pierden mensajes y hay errores al transcribir.

Decisión técnica clave Modelé el pedido como una máquina de estados (recibido → confirmado → preparación → despachado → entregado) para garantizar transiciones válidas, y validé cada webhook con HMAC-SHA256 para asegurar que las peticiones provienen realmente de Meta.

Destacado Interpretación de lenguaje natural con GPT-4o para extraer los pedidos, panel de administración con JWT y despliegue con Docker en Railway.

En números 9 endpoints REST · 37 pruebas automatizadas (pytest) · máquina de estados con 5 fases del pedido.

Portal de Bienestar ITM — API + Frontend

Mayo 2025

API centralizada para servicios de bienestar del ITM: cafetería, salud mental, biblioteca y eventos. 8 módulos, 148 tests con Vitest, caché con Redis, autenticación dual (JWT + API Keys) y CI/CD completo.

  • Node.js 20
  • Fastify 5
  • TypeScript
  • PostgreSQL
  • Redis
  • React 18
  • Railway / Vercel
Ver detalles técnicos

Problema Los servicios de bienestar del ITM (cafetería, salud mental, biblioteca, eventos) estaban dispersos, sin una API central que los unificara.

Decisión técnica clave Añadí una capa de caché con Redis para reducir la latencia en las consultas más frecuentes, y una autenticación dual: JWT para usuarios y API Keys para la comunicación entre servicios.

Destacado Cada archivo de test aísla sus datos para poder correr en paralelo sin colisiones, con un pipeline de CI/CD completo.

En números 148 pruebas (Vitest) · 8 módulos · 33 endpoints REST.

API REST de Turnos Médicos — Clean Architecture

Marzo 2025

Sistema de gestión de citas médicas con arquitectura limpia en 4 capas, reglas de negocio validadas, documentación automática con Swagger y pipeline CI/CD con GitHub Actions y deploy en Vercel.

  • Java 17
  • Spring Boot 3.3
  • PostgreSQL 16
  • OpenAPI / Swagger
  • Docker
  • GitHub Actions
  • Vercel
Ver detalles técnicos

Problema La gestión de citas médicas tiene reglas de negocio que no se pueden violar: no agendar en horarios ocupados, respetar la disponibilidad del profesional, etc.

Decisión técnica clave Apliqué Clean Architecture en 4 capas para que la lógica de dominio no dependa del framework ni de la base de datos, lo que facilita probar las reglas de negocio de forma aislada. La documentación de la API se genera automáticamente con Swagger.

Destacado Pipeline de CI/CD con GitHub Actions que corre las pruebas en cada push, y despliegue en Vercel.

En números 18 endpoints en 3 controladores · 29 pruebas · Clean Architecture en 4 capas.
